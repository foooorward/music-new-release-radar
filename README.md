# 每日新歌雷达

采集全网公开的音乐新发行数据，按**综合热度分**从高到低排序，产出每日表格 + 网页看板。

每一行都会记录：**歌名、歌手、收录平台、所在榜单、最佳名次、发布时间、跨平台数、热度分**。

---

## 快速开始

```bash
cd music-radar
python run.py
```

结束后打开 `output/dashboard.html` 即可（双击就能看，无需服务器）。

**唯一依赖是 Python 3.9+ 标准库**，不需要 `pip install` 任何东西。
如果装了 `openpyxl`，会额外多产出一份 `.xlsx`；没装就只出 `.csv`，不影响使用。

```bash
pip install openpyxl     # 可选，想要带格式的 Excel 再装
```

### 常用参数

| 参数 | 作用 |
| --- | --- |
| `python run.py` | 采集今天的数据并产出报告 |
| `python run.py --date 2026-10-09` | 指定日期（补跑 / 回填） |
| `python run.py --no-enrich` | 跳过歌手信息补充，速度快 3 倍左右 |
| `python run.py --only netease` | 只跑指定数据源，调试用 |
| `python run.py --insecure` | 关闭 TLS 证书校验，仅用于排查代理拦截问题 |

## 产出物

| 文件 | 说明 |
| --- | --- |
| `output/dashboard.html` | 网页看板（自包含单文件，数据内嵌，可离线打开） |
| `output/新歌雷达-新发行-YYYY-MM-DD.csv` | **新发行榜**：只含被平台新歌榜收录的作品，可直接交给别人看 |
| `output/新歌雷达-YYYY-MM-DD.csv` | 全量榜单：所有上榜作品按热度分排序 |
| `output/新歌雷达-YYYY-MM-DD.xlsx` | 装了 openpyxl 才有 |
| `site/index.html` | 看板的部署副本，可直接丢到任意静态托管 |
| `data/music_radar.db` | SQLite 快照库，每天一份，用于计算榜单爬升 |

两个 CSV 都是 UTF-8 带 BOM，Excel 双击不乱码。表格列：综合排名、热度分、歌名、歌手、专辑、收录平台、最佳名次、所在榜单、发布时间、近期新发行、入选新歌榜、跨平台数、上次名次、名次变化、音乐人热度、分项明细、链接。

看板支持：按平台筛选、**按数据范围筛选（默认「仅平台新歌榜收录」）**、按发布时间区间筛选、关键词搜索、点击表头排序、只看跨平台收录。

> **为什么默认是「仅平台新歌榜收录」？**
> 热歌榜、TOP500 这类榜单会收录大量几年前甚至二十年前的经典老歌，混在一起会盖住真正的新歌。默认口径只看被平台**新歌榜**收录的作品（网易云新歌榜 + 酷狗新歌榜），这才是"每日新发行"的准确范围；想看全量排行榜就切成「全部上榜作品」。

## 数据来源（全部为实测结论）

| 平台 | 接口 | 实测状态 | 拿到的字段 |
| --- | --- | --- | --- |
| **网易云音乐** | 榜单歌单接口 | ✅ 可用 | 歌名、歌手、专辑、**发行日期**、时长、歌手 ID |
| **酷狗音乐** | 移动端榜单接口 | ✅ 可用 | 歌名、歌手、音频 hash、时长、榜单名次 |
| **Apple / iTunes** | 官方搜索接口 | ⚠️ 部分可用 | 歌名、歌手、专辑、**发行日期** |

三张榜单的具体 ID 和权重都在 `config.json` 里，可自由增删：

- 网易云：新歌榜 `3779629`、飙升榜 `19723756`、热歌榜 `3778678`
- 酷狗：新歌榜 `74534`、飙升榜 `6666`、TOP500 `8888`
- Apple：中国香港 / 中国台湾区域店铺

### 三个已知限制（都是平台侧的限制，不是代码问题）

**1. 酷狗不提供歌曲发行日期。**
酷狗榜单接口里有个看着很像发行日期的字段 `rank_id_publish_date`，实测它是一个**榜单级别的字段**——同一个榜单里上百首歌的时间戳完全相同（例如新歌榜整榜都是 `2026-10-10 08:10:00`），实际含义是「这个榜单的发布时间」，不是歌曲发行日期。
所以代码**不把它当发布日期使用**，酷狗独家的歌发布日期会如实留空。作为补偿，看板提供了「仅平台新歌榜收录」这个口径——被平台新歌榜收录本身就是"它是新歌"的可靠旁证，酷狗新歌榜里那些没有日期的歌照样能被识别出来。

**2. Apple 中国大陆区域店铺的搜索接口返回空。**
实测 `itunes.apple.com/search` 在 `country=cn` 下，song / album 搜索一律返回 0 条结果（`entity=musicArtist` 正常）。中国香港、中国台湾区域店铺可用，所以默认查询这三个区域，并对连续无结果的区域自动跳过剩余请求。

**3. 跨平台匹配是启发式的。**
按「主歌手 + 歌名」做归一化比对（去标点空格、统一小写）。Live 版、Remix、重新编曲可能被合并成一条，也可能漏配。识别不出的版本差异没法靠规则彻底解决。

## 综合热度分怎么算

```
热度分 = 100 × (榜单名次×0.45 + 跨平台覆盖×0.25 + 音乐人热度×0.15 + 榜单爬升×0.15)
```

权重在 `config.json` 的 `scoring.weights` 里，可以自己调。**任一维度缺失时会按比例把权重分摊给其它维度**，不会因为某个平台没采到数据就整体压低分数。

- **榜单名次** — 该曲在所有**真实榜单**中按榜单权重加权平均的名次分（第 1 名 = 1.0）。
  Apple 的清单是按发行时间排序的，名次只代表新旧，因此权重设为 0，不参与计分。
- **跨平台覆盖** — 出现在几个平台。只用一个平台采集时会退化成中性值，避免所有歌同分。
- **音乐人热度** — 代理指标：`0.65 × 本次榜单曝光度 + 0.35 × 作品体量`。
  作品体量取自平台公开的作品数 / 专辑数（对数归一）。**这不是真实粉丝数**，因为所有国内平台都不公开歌手粉丝量。
- **榜单爬升** — 与上一次快照中该曲的最佳名次对比。**第一次运行是中性的，从第二天起才有真实意义。**
  这是整套系统里唯一靠单次请求拿不到、只能靠持续采集积累的信号，也是它最有价值的部分。

## ⚠️ 关于「播放量」这件事

你原始需求里的「按播放量排序」，在现实里做不到，原因如下：

**网易云、酷狗、QQ 音乐都不对外公开真实播放量。** 实测网易云接口里的 `pop`（热度）字段返回空值，页面上看到的"热度""飙升指数"都是平台内部算法算出来的值，不是播放次数。

**真正公开播放量数据的只有两个来源：**

| 来源 | 字段 | 接入成本 |
| --- | --- | --- |
| YouTube Data API v3 | `viewCount` | 需申请 API Key，每日配额 10000 单位 |
| Last.fm API | `playcount` / `listeners` | 需申请免费 API Key |

代码里已为这两者预留了接入位（`scoring.py` 中音乐人热度部分可以直接接入外部数据）。需要的话可以加上，但要先准备好 Key。

所以本工具按**综合热度分**排序 —— 它综合了榜单名次、跨平台铺量、音乐人体量和爬升趋势，比单一播放量更抗刷量，也更适合"发现新歌"这个目的。

## 合规与使用边界

- 三个数据源里，只有 Apple 是**官方公开 API**。网易云、酷狗走的是它们 Web / 移动端的公开接口，**不是官方开放 API**。
- 代码已经把请求限速做到最低限度：每个数据源之间有延迟，单次运行只需几十个请求。**请保持每天 1～2 次的频率。**
- 高频抓取会触发平台风控、封锁 IP。
- 采集到的数据**仅供个人研究使用，不要商用，也不要再公开分发**。
- 数据版权归各平台与版权方所有。

## 目录结构

```
music-radar/
├── run.py                    # 入口，串起采集 → 打分 → 产出的全流程
├── config.json               # 数据源、榜单、权重、关键词，都在这里改
├── music_radar/
│   ├── http_client.py        # 统一请求层：限速、重试、gzip、可选跳过证书校验
│   ├── sources.py            # 三个平台的采集器 + 歌手信息补充
│   ├── scoring.py            # 跨平台聚合去重 + 综合热度分模型
│   ├── store.py              # SQLite 每日快照
│   └── report.py             # CSV / Excel / 网页看板
├── data/music_radar.db       # 快照库
├── output/                   # 每日表格 + 看板
└── site/index.html           # 看板的部署副本
```

想加数据源的话，只要在 `sources.py` 里写一个 `collect_xxx(cfg, log)` 函数，返回统一结构的列表，再登记到文件末尾的 `COLLECTORS` 里就行。

## 常见问题

**酷狗报 TLS 证书错误（`CERTIFICATE_VERIFY_FAILED`，主机名不匹配）**
说明你所在网络有 TLS 中间人（公司代理、安全软件、部分运营商）。这是网络环境问题，不是接口问题。把 `config.json` 里酷狗的 `insecure_ssl` 改成 `true`，或运行 `python run.py --insecure`。
注意：这会关闭证书校验，降低连接安全性，只在确实有代理拦截时使用。

**Apple 一条数据都没有**
先确认 `config.json` 里 `itunes.countries` 包含 `hk` 或 `tw`。中国大陆区域店铺（`cn`）的搜索接口返回空，这是苹果侧的限制。

**榜单爬升列全是「—」**
正常。爬升需要至少两天的快照做对比，连续运行两天后就会出现。

**想改排序规则 / 只关注某些风格的歌**
编辑 `config.json`：`scoring.weights` 调权重，`sources.*.charts` 增删榜单，`output.title_blacklist` 过滤不想看到的标题关键词（默认已过滤「伴奏」「DJ版」「纯音乐」「翻自」）。
